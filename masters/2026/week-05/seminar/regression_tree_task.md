**Задача:** самостоятельно разработать `MyDecisionTreeRegressor` — учебное дерево для регрессии — и проверить его поведение. **Готового скелета регрессора нет:** нужно разобраться в исходной реализации и решить, что можно перенести, а что должно измениться.

## 1. Что должно работать

Создайте класс `MyDecisionTreeRegressor`, для которого выполнены следующие условия:

1. Метки целевой переменной — **вещественные числа**, а прогноз — числовое значение, не класс и не вероятность класса.
2. Дерево ищет разбиения числовых признаков по уменьшению **MSE** (или, эквивалентно для одного узла, суммарной RSS после разбиения).
3. Лист возвращает **среднее значение целевой переменной** среди обучающих объектов, попавших в этот лист.
4. Реализованы `fit(X, y)` и `predict(X)`. `fit` сохраняет обученную структуру и позволяет затем получить прогноз для новых объектов.
5. Поддерживаются ограничения `max_depth`, `min_samples_split`, `min_samples_leaf` в том же содержательном смысле, что в классификаторе.
6. Код корректно работает на обычных числовых `numpy`-массивах без пропусков. Не требуется поддержка категорий, `NaN`, sample weights и расширенного API scikit-learn.

Внутреннее представление дерева и организация кода — ваш выбор. Можно сохранить формат и методы исходного класса либо осмысленно изменить их. Главные требования — корректность алгоритма и возможность объяснить его устройство.

**Не используйте `sklearn.tree.DecisionTreeRegressor` внутри собственной реализации** для построения структуры или вычисления прогнозов. Библиотечная модель нужна только для независимого сравнения результатов.

## 2. Контрольный пример из лекции

Используйте шесть наблюдений:

```python
import numpy as np

X = np.array([[1.], [2.], [3.], [4.], [5.], [6.]])
y = np.array([1., 2., 1., 7., 8., 9.])
```

Для дерева **максимальной глубины 1** без других ограничений, мешающих этому разбиению, лучший порог — **3.5**. Левая группа содержит ответы `(1, 2, 1)`, правая — `(7, 8, 9)`.

Ожидаемые прогнозы для шести исходных `X`:

```python
np.array([4/3, 4/3, 4/3, 8., 8., 8.])
```

Средняя квадратичная ошибка на этих шести объектах составляет **4/9 ≈ 0.4444**. Проверьте, что ваша модель воспроизводит этот результат с достаточной численной точностью (например, через `np.allclose`).

Дополнительно проверьте хотя бы один простой крайний случай на свой выбор: постоянную целевую переменную, одинаковые значения признаков, недопустимость слишком маленького дочернего узла либо прогноз нового объекта за пределами обучающих значений.
